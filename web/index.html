How this book is kept four files, one binary

A scorebook, a simulator, the proofs that constrain both, and the harness that drives them against real games.

  1. The scorebook is one function, and it is proven.

    game.bend holds the state of a game and the single step that applies one completed play. Every moving runner is first taken off its origin and held, then placed, so exchanges and force plays need no special cases. A play that cannot be applied legally returns None and is counted as rejected, never silently dropped.

    # take every origin, then place every destination
def take_all(p: Play, h: Half) -> Maybe<&2, Pending>
def put_all(m: Maybe<&2, Pending>) -> Maybe<Half>

def step(+s: State, p: Play) -> State:
  after(s, slots(p, half_of(s)))

  2. 2d games fork across the GPU.

    sim.bend plays 2d games forward from the current scorebook state, each one driven by the same proven step. Plate appearances are integer draws against cumulative thresholds, no floating point in the engine, and tree! runs the identical program on the GPU.

    def tree(d: Nat, +i: U32, +c: Ctx) -> Tally:
  match d:
    case 0n:   tally_of(one(i, c))
    case 1n++p:
      a b = tree(p, i, c) tree(p, (i + U32.from_nat(pow2(p)) : U32), c)
      tally_add(a, b)

  3. The invariants are theorems.

    LAWS.bend states what must hold for every input; PROOF.bend proves each one by induction and case analysis, and bend PROOF.bend must print ALL PROOFS CHECK before any commit. The four laws are tabled under Proof of box score.

  4. The harness replays real games.

    live.py pulls the MLB Stats API feed: completed plays, the official homeTeamWinProbability, and each team's season batting line. It turns the batting line into seven cumulative thresholds out of 10,000 (K, O, W, S, D, T, H), encodes each play into four destination slots (r3 r2 r1 batter, chars - X R 1 2 3), and runs the compiled wp once per play. Results stream to runs/<gamePk>.csv and are POSTed to a Cloudflare Worker whose Durable Object this page polls every 5 s. No framework: one HTML file, one Worker, one binary.

Proof of box score OBR 9.03(c)

A scorekeeper proves a box score by checking that each team's plate appearances balance its runs, putouts and runners left on base. Here that check, and three others, hold for every possible input, because they are proven about step itself.

Reproduce offline by default

Fixtures are cached; nothing is fetched unless asked.

git clone https://github.com/harlanljones/bend-winprob && cd bend-winprob
bend PROOF.bend                            # ALL PROOFS CHECK
python3 sim_engine.py --pk 849805          # replay World Series Game 1, 65,536 sims/play
python3 bench.py                           # the 12-game benchmark above (GPU, depth 20)
python3 -m unittest discover -s tests -v

This page and its feed are one Cloudflare Worker with a single Durable Object (cloudflare/): live.py --publish POSTs each new CSV and the page polls it, falling back to the bundled replay when nothing is published. Open ?pk=<gamePk> for another game. bash run_live.sh supervises a live game with backoff and logs every run.

Notes what this card does not know

  • Season-level team rates. Plate appearances are i.i.d. draws from each team's season distribution: no batter, pitcher, platoon, park, umpire, weather, leverage or bullpen state.
  • A four-slot play encoding. A play is four destinations (r3, r2, r1, batter). Pickoffs, caught stealings, wild pitches and passed balls do not fit and are refused: 29 of 871 plays in the benchmark, 0 in the bundled replay.
  • Small sample. 12 games and 871 plays, with per-game Brier from 0.03 to 0.30. Treat the aggregate as suggestive, not settled.
  • A benchmark, not a claim of superiority. MLB's win probability is a production model with far more information than this proof of concept uses.
  • Not a betting tool. It is a demonstration that a proven, parallel scorebook can track a production model on real data. Where a prediction market lists the game, its price is shown as a reference, not as ground truth.
